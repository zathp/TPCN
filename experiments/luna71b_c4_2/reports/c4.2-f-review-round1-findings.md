## Findings

### F-01 — Corrective feedback bypassed the application ordinal

The source-level corrective-feedback branch emitted `feedback_apply`
directly, deriving `application_order` from event processing order. It did
not use `SourceCapture.feedback_applied()`'s distinct per-capture ordinal.
The existing helper test did not cover that direct emitter. The source also
represented corrective feedback as an ordered four-class sign vector, while
the PPC-11 C4.2 schema validator accepted only scalar signs.

**Correction:** Route ordinary and corrective feedback application through
the shared helper. Preserve the source corrective-sign vector as four exact,
typed integer signs and validate its cardinality/values; leave existing
scalar signs and exact ordered comparison intact. Add synthetic coverage for
the helper and both copied source call sites. Corrective scheduling
provenance and the rest of the P08 lifecycle remain incomplete.

### F-02 — Eligibility admission reason used total occupancy

The capture hook labeled an admission `"existing_trace"` whenever the ledger
had any trace. That does not prove that the incoming trace ID already
existed, and the value was read before the ledger's decay/expiry step.

**Correction:** In the isolated C4.2 ledger copies, add a capture result that
returns the actual post-decay trace-ID reuse decision and occupancy at the
admission boundary while preserving `record_activity()`'s existing return
value and no-capture call path. Source hooks use that decision. Synthetic
tests cover a new ID when another trace exists, a repeated ID, and an ID
recreated after expiry. Eligibility expiry event and capacity/rejection
capture remain incomplete.

### F-03 — Historical summary count and status wording

The pre-existing C4.2 `final-independent-review.md` referred to seven
correction-evidence entries, but the JSON index contains eight. The source
inventory/correction-index use `INCOMPLETE — CORRECTION REQUIRED` for
overall evidence readiness, while the bounded correction report and review
say the narrow implementation correction passed.

**Reconciliation:** This C4.2-F history records the correct eight-entry
count and distinguishes the overall PPC-11 readiness disposition
(`INCOMPLETE`) from the bounded code-correction review disposition
(`PASS`). The original C4.2 report and index bytes remain historical and are
not silently rewritten. The eight original evidence hashes matched at that
revision; two indexed files (the source manifest and test) have since been
superseded by the separately hashed C4.2-F revision.
