## Decision

**PASS — TPCN-IR-2 SCHEMA ACCEPTED FOR IMPLEMENTATION AND INDEPENDENTLY
VERIFIED; E2/M REMAINS UNAUTHORIZED.**

This ACP defines the versioned, hardware-neutral representation required to
transfer and reconstruct the accepted ACP-0004 E1 excursion-neuron state. It
does not implement E2/M, a backend, learning, H2, ACP-0002 N3, or any hardware
mapping. E2/M remains unauthorized pending separate implementation and
independent closure.

`TPCN-IR-1` remains frozen for its accepted H1 scope. An IR-1 reader must
explicitly reject an excursion-neuron record; it must never reinterpret it as a
legacy `tanh` neuron.

## Schema identity and compatibility

The root record has an explicit discriminator:

```text
ir_version: "TPCN-IR-2"
schema_revision: 1
```

Every neuron has an explicit dynamics discriminator:

```text
dynamics_model: "TANH_LEGACY" | "EXCURSION_V1"
```

Unknown versions, revisions, or dynamics models fail validation explicitly.
IR-2 may represent a valid IR-1-compatible network only when it is explicitly
tagged `TANH_LEGACY`. A deliberate upgrade is:

```text
IR-1 TANH network -> IR-2 TANH_LEGACY network
```

The upgrade does not fabricate excursion state. `EXCURSION_V1` is never
inferred from optional fields. The default downgrade is unsupported:

```text
IR-2 EXCURSION_V1 -> IR-1 = explicit unsupported error
```

## Canonical record model

IR-2 contains canonical network configuration, bounded topology and the
excursion-aware transferable execution state required by the supported
reference reconstruction path. It is not a complete arbitrary live-runtime
checkpoint for all TPCN subsystems.

An `EXCURSION_V1` neuron record contains, at minimum:

```text
neuron_id
dynamics_model
x
local_last_update_time
mode: N | S_PENDING | S_RETURN | M_ACTIVE
lambda
X_max
theta_R, theta_E, theta_hold, theta_M
Delta_t_E, Delta_t_M_emit, Delta_t_M_rearm, Delta_x_E
A_min, A_max
provenance_capacity
event_budget/configuration
```

All times and numeric values are finite, local logical values. The canonical
constraints are those of ACP-0004, including
`0 < theta_R < theta_E <= theta_hold < theta_M <= X_max`,
`lambda > 0`, positive finite delays, `0 < Delta_x_E <= X_max`,
`0 < A_min <= A_max`, and `1 <= P <= 64`.

`y` is not persistent canonical state. A geometric projection may be carried
only as non-semantic visualization/reference data outside the execution state.

## Pending internal events and ordinary episodes

The record contains the one currently valid pending internal event, or no
event. It does not serialize stale queue artifacts as canonical state:

```text
pending_internal_event:
  neuron_id
  kind: S_EMIT | S_REARM | M_EMIT | M_REARM
  timestamp
  episode_id
  generation
  queue_sequence
```

`queue_sequence` is deterministic ordering metadata only. It is distinct from
causal event identity. The destination-local policy is explicitly versioned:

```text
execution_order_policy:
  "DESTINATION_LOCAL_EXTERNAL_BEFORE_INTERNAL_V1"
```

For `S_PENDING`, the record requires an ordinary episode ID, bounded lineage
ID, captured polarity (`-1` or `+1`), `m_peak`, and exactly one valid
`S_EMIT`. For `S_RETURN`, it retains the ordinary episode and lineage, never
permits a second `S_EMIT`, and carries zero or one valid `S_REARM` according to
the closed E1 state. Mode and pending-event combinations are validated rather
than inferred.

## Provenance and identity continuity

The bounded provenance ring contains, per entry:

```text
causal_event_id
timestamp
signed_contribution
episode_id
lineage_id
```

The record also carries `provenance_capacity`, active count and
`provenance_truncated`. Oldest eviction and truncation state are preserved;
truncated attribution is never reconstructed as complete. No unbounded array
is legal.

The transferable state includes monotonic next/allocation counters or
equivalent high-water marks for excursion/event identity, ordinary episode
identity, lineage identity, input identity where used, and generation tokens.
Counters are bounded by the declared execution budget and must not wrap.
Causal event identity is not queue insertion sequence. Reconstruction followed
by continued execution must not reuse any pre-serialization event, episode or
lineage identity.

Reset and transfer are different operations. Reset clears character-local
episode/provenance state according to the canonical implementation while
retaining monotonic identity counters. IR-2 reconstruction restores the
serialized state and must not invoke reset semantics.

## M representation without M execution

IR-2 represents accepted ACP-0004 M configuration and state so the schema does
not need another version when E2 is separately considered:

```text
mode: M_ACTIVE
m_phase: ARMED | REFRACTORY
multi_episode_id
Delta_t_M_emit
Delta_t_M_rearm
Delta_x_E
theta_hold
pending M_EMIT or M_REARM
final-residual transition fields where required
```

An IR-2 record with `M_ACTIVE` is valid schema data, but an E1-only reference
runtime must return an explicit unsupported-runtime error. It must not
downgrade M to E1 or silently emit an ordinary excursion.

## E2 reconstruction capability boundary

The existing E1-only adapter remains:

```text
neuron_from_ir2(record)
```

It consumes the same validated `IR2Neuron`/`TPCNIR2` objects as every
supported adapter and continues to raise `IR2UnsupportedRuntimeError` for
`M_ACTIVE`. It must not silently become E2-capable.

The separately named E2-capable paths are:

```text
neuron_to_ir2_e2(neuron)
neuron_from_ir2_e2(record)
```

They share IR-2 parsing and validation rather than forking schema rules.
`neuron_from_ir2_e2` supports `N`, `S_PENDING`, `S_RETURN`,
`M_ACTIVE/ARMED` and `M_ACTIVE/REFRACTORY`. ARMED reconstruction restores the
original `M_EMIT` pending record; REFRACTORY reconstruction restores the
original `M_REARM` pending record. Neither path schedules a duplicate event
or changes the phase.

E2 reconstruction preserves the common monotonic episode high-water mark,
lineage and event/input counters. M-to-final-S continuation uses a newly
allocated ordinary episode identity from the shared counter, the existing
lineage, re-owned active provenance and sticky truncation. Reset semantics are
not invoked during reconstruction. These clarifications do not require an
IR-2 schema revision; `schema_revision` remains `1`.

## Network, Model-B and runtime scope

IR-2 preserves ACP-0002 N2 edge fields exactly: `w`, `d`, `r`, positive
propagation delay and routing metadata. For an excursion source,
`a_i = p_exc`; downstream Model-B transfer is unchanged. Pending external
events are not claimed as a universal live queue checkpoint. A supported
reconstruction path may represent the bounded external-event set it explicitly
owns, but must declare its ordering and scope.

The following are excluded unless separately represented by a later schema:

- complete prediction-matching state;
- eligibility state;
- reward-idempotency state;
- energy/accounting history;
- arbitrary backend execution state;
- calibration state;
- unrepresented structural-learning runtime state;
- arbitrary queue, host, device, or live scheduler state.

`TPCV-1` remains downstream-only visualization and is not IR-2.
Canonical logical state, backend realization state and calibration state remain
separate under ACP-0003. IR-2 does not establish E0-E4 equivalence claims.

## Validation and deterministic serialization

JSON remains permitted only with deterministic key/record ordering, explicit
version fields, exact enum encoding, finite-number validation and stable
round-trip behavior. Implementations must reject unknown versions/models,
invalid modes or M phases, impossible pending-event combinations, non-finite
values, invalid threshold ordering, invalid capacities/counts, invalid
polarity, prohibited negative IDs, duplicate causal identities, wrong
neuron/episode ownership and pending timestamps earlier than local time.

The implementation acceptance fixtures are:

1. N, S_PENDING and S_RETURN round trips;
2. non-default E1 configuration;
3. S_EMIT and S_REARM preservation;
4. admission polarity and `m_peak`;
5. exact non-truncated and truncated provenance;
6. identity-counter continuation and stale-generation rejection;
7. non-default Model-B edge transfer;
8. destination-local equal-time ordering;
9. explicit M validation and E1-only M rejection;
10. unknown version/model and malformed cross-field rejection;
11. deterministic serialization;
12. explicit IR-1 upgrade, excursion downgrade rejection and TPCV separation;
13. full legacy regression suite.

These are implementation acceptance checks, not results of this architecture
decision. No IR-2 runtime or backend tests have been run.

## A01-A15 and authorization boundary

All A01-A15 clauses are unchanged and preserved. IR-2 preserves logical
scheduled events (A01), local elapsed state without a global clock (A02),
finite delays (A03), bounded topology/state (A04/A08), the predictive-coding
boundary (A06), bounded provenance compatible with delayed credit (A11), and
hardware-neutral semantics (A15). A05 remains reservoir-free; A12-A13 remain
optional; A14 is not activated.

Luna-20 is authorized only to implement and verify the IR-2 schema,
deterministic serialization, E1 conversion/reconstruction, explicit IR-1
upgrade/rejection boundaries, future M representation, and the listed tests.
It must not implement M runtime, E2, backends, learning, H2, N3, hardware,
calibration, or modify canonical E1 behavior except for directly required
serialization hooks.

ACP-0003 H2, ACP-0002 N3, Luna-13F reopening and Luna-13G remain unauthorized.
