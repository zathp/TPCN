## Current invariant or soft constraint

ACP-0002 N2 is closed and remains authoritative for the static Model-B edge
transfer:

```text
z_ij = tanh(w_ij * a_i)
v_ij = d_ij * z_ij + (1 - d_ij) * r_ij
```

The contribution `v_ij` arrives after its finite positive propagation delay and
is processed with local elapsed-time decay and deterministic equal-time
ordering. ACP-0003 is accepted for staged implementation; H1
(`TPCN-IR-1`) is closed. A01-A15 remain unchanged.

This proposal changes canonical neuron output semantics and therefore requires
an explicit architecture decision. It does not authorize ACP-0003 H2,
ACP-0002 N3, a production backend, calibration, hardware equivalence,
Luna-13F reopening, Luna-13G, or a Luna-19 implementation.

## Observed problem

**OBSERVED:** Several delayed signed contributions should be able to alter one
bounded local state and produce fewer downstream emissions, while excessive
excitation must be able to produce a bounded sequence of emissions. Existing
documentation also uses “spike” for both software events and physical analog
behavior.

**HYPOTHESIZED:** A leaky signed accumulator with explicit bounded return
trajectories can provide compression and controlled multi-excursion output
without a global timestep or unbounded recurrent activity.

No runtime or hardware evidence establishes this hypothesis at the proposal
revision.

## Proposed canonical boundary

The backend-neutral object is a **canonical excursion**. It is not a spike,
CUDA operation, FPGA clock pulse or analog voltage. The realizations are:

| Canonical meaning | GPU/software and FPGA reference | FPAA realization |
|---|---|---|
| One canonical excursion | exactly one canonical digital emission event | one physical spike or analog excursion within a later approximation contract |
| Multiple excursions | multiple digital emission events | multiple physical spikes or analog excursions |
| Logical timestamp | deterministic logical emission timestamp | physical peak/crossing time is observational |

The one-to-one digital cardinality is a required acceptance condition. A
backend must not represent one canonical excursion with an unspecified number
of digital events. If a later design genuinely needs multiple digital records,
it must define one excursion identity, record types, ordering and bounded
cardinality in a new reviewed extension.

Compression and multi-excursion encoding are distinct:

```text
C_E = N_input_contributions / N_output_excursions
```

GPU/FPGA reference observables use
`N_output_excursions = N_output_events`. FPAA observables use physical
excursion/spike counts subject to an explicitly declared approximation
tolerance. A multi-excursion return is not evidence of compression.

## Canonical state and event update

The proposed persistent dynamical state is:

- signed accumulator `x`, with `-X_max <= x <= X_max`;
- local last-update timestamp `t_last`.

The following are bounded execution bookkeeping, not an independent
unbounded dynamical coordinate:

- mode and ordinary-return phase;
- multi-excursion generator arm/disarm phase;
- pending excursion identity and captured polarity;
- bounded provenance lineage and truncation status;
- bounded excursion amplitude;
- at most the declared finite set of pending internal emissions.

`y` may be a derived trajectory coordinate, but is not persistent canonical
state in this proposal. Any later independent persistent coordinate requires
evidence that `x` plus bounded bookkeeping loses required causal information.

For an arrival at local time `t_k`, the canonical accumulation equation is:

```text
x(t_k-) = x(t_(k-1)+) * exp(-lambda * (t_k - t_(k-1)))
x(t_k+) = clip[-X_max, X_max](x(t_k-) + v_ij(t_k))
```

There is no global neural timestep. Equal-time arrivals are processed
sequentially by the existing deterministic sequence order; the first arrival
may change the mode before the second is processed. `lambda`, `X_max`,
timestamps, delays and all mode/bookkeeping capacities must be finite and
validated.

## Operating regions and transition requirements

The parameters must satisfy:

```text
0 < theta_E < theta_M <= X_max
0 <= theta_hold < theta_M
```

The region tests are exact and use inclusive/exclusive boundaries:

```text
N: |x| < theta_E
S: theta_E <= |x| < theta_M
M: |x| >= theta_M
```

The review requires the following transition semantics before acceptance:

- region membership is evaluated after each ordered accumulation or due local
  internal event;
- `N -> S` or `N -> M` occurs when the post-update value enters that region;
- an active ordinary return does not emit again merely because later input
  remains in `S`;
- `S -> M` is possible when a new ordered input makes `|x| >= theta_M`;
- `M` remains active while `|x| > theta_hold`;
- `M -> S` occurs when `|x| <= theta_hold`, followed by the ordinary return;
- a return episode is re-armed for a new ordinary excursion only after its
  prior ordinary return has completed and the neuron has reached `N`.

These rules prevent threshold chatter and make a moderate overshoot produce
at most one ordinary excursion per return cycle.

## Ordinary excursion

An ordinary return must be a bounded, distinct return trajectory that:

1. begins from the accumulated state that entered `S`;
2. emits exactly one canonical excursion;
3. has bounded amplitude;
4. terminates after finite local progression; and
5. converges toward `N` without requiring new input.

The exact lobe geometry is not canonical unless it is fixed by a later
decision. A normalized fixture may be used to test it, but a backend may not
invent a different semantic trajectory while claiming equivalence.

The payload is signed and bounded:

```text
p_exc = sign(E) * A_exc
0 <= A_exc <= A_max
```

The amplitude map must be deterministic, finite, bounded, monotone over its
declared input range, and explicit about saturation. Its sign source must be
defined; the required first-stage choice is the sign captured when the
excursion is admitted, so later input cannot silently mutate an already
identified excursion.

## Multi-excursion return

Entry is exactly `|x| >= theta_M`. The multi-excursion generator must expose a
bounded armed/disarmed state with:

```text
h_min <= h <= h_max
h_L < h_H
```

`h_L` and `h_H` are oscillator/re-arm coordinates. They must not be compared
directly with `theta_hold`, which is an `x`-domain threshold. The invalid draft
condition `h_L >= theta_hold` is removed. The independent accumulated-state
condition is `0 <= theta_hold < theta_M`.

Each generator cycle must define, without backend interpretation:

1. armed state;
2. trigger condition;
3. exactly one emitted excursion;
4. disarm transition;
5. re-arm condition; and
6. eligibility for the next excursion.

Per-excursion discharge must use the smallest provable first-stage rule:

```text
x <- sign(x) * max(|x| - Delta_x_E, 0)
Delta_x_E > 0
```

This cannot cross zero or reverse polarity. A multi-excursion return exits
only at `|x| <= theta_hold`, then enters the ordinary return and eventually
reaches `N`; it does not jump directly to an unobserved reset.

With no new input, the discharge ranking bound is:

```text
0                                      if |x_0| <= theta_hold
ceil((|x_0| - theta_hold) / Delta_x_E) otherwise
```

The bound is valid for `|x_0|` in `[theta_M, X_max]` only if every discharge
has the saturating rule above and each generator cycle has finite duration.
The `|x_0| = theta_M`, `|x_0| = X_max`, negative-state and zero-crossing cases
must be fixtures, not assumptions.

## Input during autonomous return

An input arriving during either return is processed at its timestamp using the
same local decay, clipping and deterministic ordering as any other input. It
cannot be dropped. Before acceptance, the implementation contract must fix
these cases:

- during ordinary return, whether the not-yet-emitted amplitude is recomputed
  from the updated `x`, and when `S -> M` occurs;
- after an ordinary emission, how later input is retained for the next episode;
- during multi-excursion return, how input extends discharge, affects the
  generator, or changes the active episode;
- how an opposite-sign input is retained without mutating the identity or
  polarity of an already emitted excursion.

The required first-stage policy is: process input before any same-timestamp
later internal transition, update `x`, promote `S -> M` on the exact boundary,
and never retroactively change an emitted payload. Any pending input that
changes sign remains in `x` and is handled by a subsequent deterministic
episode. The remaining phase/amplitude details must be written as executable
transition rules before implementation authorization.

## Logical autonomous events and timing

Return progression that continues without an external arrival must be
represented by bounded internal neuron events scheduled at finite future
logical timestamps. It must not be implemented as a hidden timestep loop.

The canonical first stage must declare:

- a positive finite ordinary-return delay `delta_S`;
- a positive finite inter-excursion delay `delta_M`;
- timestamp calculation from the triggering event and local state;
- equal-time ordering between external and internal events;
- at most the declared finite number of outstanding internal events per
  neuron;
- cancellation/rescheduling when a new input changes the active return.

Emission occurs at the declared logical return transition, not at an
implementation-dependent physical peak. These timing and cancellation
semantics are currently missing from the draft and block acceptance.

## Event identity, provenance and predictive coding

Every digital emission receives a unique non-negative event sequence/identity
and deterministic timestamp. Multiple excursions from one episode share a
bounded lineage identifier while retaining distinct event identities.

Provenance must have an explicit finite capacity `P`. The required overflow
policy is oldest-contributor eviction plus an explicit `provenance_truncated`
flag. Once eviction occurs, delayed-credit attribution must not claim complete
history; it may credit only retained contributors or use a separately declared
aggregate.

Accumulator changes remain local internal evidence. Predictions are emitted
only through canonical excursions, and prediction errors remain explicit
causally propagated events. Bounded lineage/provenance must be sufficient for
the declared delayed-credit behavior, or its attribution limitation must be
reported. Labels, future points and global evaluation state remain outside
canonical state.

## Model-B source semantics and compatibility

After excursion migration, the Model-B source value is defined as:

```text
a_i := signed excursion payload p_exc
```

Thus an emitted digital event supplies `a_i` to
`z_ij = tanh(w_ij * a_i)`. The former continuously recomputed
`a_j = tanh(g_j * s_j)` is an internal compatibility/diagnostic value only
and is not a second canonical outgoing stream.

Legacy continuous-output behavior may remain only as an explicitly named,
trace-labelled compatibility mode for historical comparisons. It cannot
silently coexist as another canonical output and its Model-B source semantics
must identify the mode that produced the payload.

Because IR-1 accepts only the existing `tanh` neuron semantics, excursion
state, modes, pending internal events, payload rules and provenance require a
new explicitly versioned schema, strongly expected to be `TPCN-IR-2`.
IR-1 readers must reject excursion records rather than silently reconstruct
them as legacy continuous neurons. No IR-2 implementation is authorized here.

## A01-A15 impact

A01, A02, A03, A04, A06-A08, A09-A11 and A15 are preserved but receive the
explicit requirements above if the proposal is accepted. A05 remains
preserved; no spatial reservoir is introduced. A12-A13 remain optional.
A14 is not activated. The proposal does not amend the architecture contract.

## Required implementation stage if accepted

The smallest authorized stage would be **E1 — static canonical leaky
accumulator plus single-excursion return**:

- implement `x`, local elapsed decay, clipping and exact N/S boundaries;
- implement one bounded excursion with one digital event per excursion;
- implement explicit amplitude, polarity, timestamp and provenance semantics;
- implement finite internal-event scheduling and deterministic return;
- exclude the multi-excursion generator, learning, backend approximations and
  IR-2 until E1 is independently verified.

E1 must include deterministic compression/leakage, anti-burst, signed,
equal-time and input-during-return fixtures. A later stage may implement M only
after E1 and a separate bounded M contract are reviewed. No Luna-19 dispatch is
created by this draft review.

## Review decision and unresolved blockers

**ACP-0004 REMAINS DRAFT — NOT ACCEPTED FOR STAGED IMPLEMENTATION.**

The proposal is directionally coherent but the committed draft did not define
enough canonical semantics for a backend-neutral implementation. Acceptance is
blocked until the proposal itself resolves:

1. exact internal-event timestamps, positive delays, equal-time ordering and
   cancellation/rescheduling;
2. complete ordinary-return and input-during-return transition tables;
3. complete multi-excursion generator transitions and input behavior;
4. explicit finite provenance capacity and overflow/truncation semantics;
5. one-to-one excursion-to-digital-event identity and lineage rules;
6. exact amplitude-map contract and sign source;
7. versioned IR migration, including the required excursion schema; and
8. deterministic fixtures proving finite return and bounded pending work.

These are architecture blockers, not production-code defects. No empirical
claim is made until an authorized implementation and independent verification
produce the required evidence.
