## Current invariant or soft constraint

A14 currently permits connections and computational resources to change from
locally obtainable evidence while respecting hardware/topological constraints.
The existing A04 hard limits remain unchanged. The current wording does not
make a legal route to useful convergent fan-in, explicit capacity-failure
accounting, or structural-organization measurements normative.

## Observed problem

The 12D and 12E handoffs report repeated duplicate proposals and alternating
growth/pruning churn, with no measured final functional benefit. The current
`StructuralPlasticityController` records several rejection causes but does not
make complete cause accounting or attainable convergent structure an
architectural obligation. This is an observed governance gap, not evidence
that a temporal-association rule will work.

## Proposed change

Revise A14 so bounded fan-in/out, edge and routing capacities remain resource
limits while an enabled structural policy must preserve a legal, measurable
route to useful convergent causal structure. Require explicit bounded
admission/replacement/pruning decisions and rejection causes. Permit local
causal temporal relationships and finite-delay path shortening as experimental
signals without requiring any timing window, matching rule, correlation
formula, path-shortening equation or fan-in heuristic. A new edge remains a
new finite-delay causal path and cannot alter past or in-flight events.

Clarify under A07 that offline/module bootstrap may prepare reproducible
initial state but cannot supply hidden global runtime inputs. Bootstrap remains
a supported direction, not a mandatory initialization mode.

## Why implementation alone cannot solve it

The change defines what future structural-learning policies must preserve and
what evidence they must report. An implementation can add counters or a
candidate heuristic, but cannot locally decide whether the architecture
requires convergent capacity or whether an experiment has crossed the
promotion boundary. Those are contract and governance decisions.

## Expected benefits

- Prevents bounded-resource compliance from being mistaken for useful topology
  formation.
- Makes duplicate churn, capacity exhaustion, locality rejection and utility
  rejection distinguishable.
- Permits multiple causal structural-learning hypotheses while keeping them
  falsifiable and hardware-aware.
- Separates offline initialization orchestration from runtime local learning.

## Expected disadvantages and risks

- Future policies need additional instrumentation and matched controls.
- A policy may pass resource checks yet fail to form useful convergence; the
  contract intentionally does not guarantee task improvement.
- More explicit diagnostics may expose existing API gaps or unavailable edge
  utilization data.
- The phrase "useful convergent structure" requires operational definitions in
  each experiment and must not become an invented universal accuracy target.

## Hardware implications

Admission, replacement, pruning, fan-in/out, edge, candidate and routing
budgets must be representable with finite hardware state. Positive propagation
delays and non-retroactive path creation preserve FPGA/VHDL, FPAA and hybrid
mapping. Temporal evidence may use local timestamp/elapsed-time metadata or
bounded event history; a hardware clock may meter or schedule implementation
work but cannot become a neural timestep. Software-only global graph searches
are not canonical mechanisms.

## Learning and energy implications

Temporal evidence may affect structural preference only through causally/local
available activity. Labels, global evaluation metrics and future events remain
outside canonical structural decisions. Structural churn and candidate
processing must be included in local resource/utility measurements where the
chosen model supports them. Delayed credit remains governed by A11 and is not
replaced by a global topology objective.

## Compatibility and migration

Existing fixed-topology operation, disabled structural plasticity, random and
simple deterministic initialization remain legal. Existing Luna-4 topology,
Luna-10 controller, Luna-12E routing, Luna-12F readout, Luna-12G benchmark and
Luna-12H temporal semantics remain usable. Luna-13 through Luna-17 meanings
and independent dependency gates are unchanged. Existing artifacts that lack
per-edge traffic must report that field as unavailable rather than infer it.

## Required experiments and acceptance criteria

Luna-12I must compare fixed topology, the existing policy, random legal
candidates and temporal-association candidates with matched seeds, resource
budgets, workload, reset policy and training effort. Timing-shuffled and
reversed-order controls should be added where practical. Measure fan-in/out,
convergent motifs, edge utilization, accepted/rejected growth with explicit
reasons, duplicates, path lengths/delays, shortening, replacement/pruning,
churn, events, prediction error, energy/resource proxy, utility, task behavior
and determinism. A negative result remains valid evidence.

The previously reserved modular/bootstrap Luna-12J concept is not an active
numbered milestone in the current workflow. The current Luna-12J dispatch
instead separately tests temporal-associative structural efficacy and causal
attribution against fixed, pre-12I, random-legal and temporal-growth controls,
using the persistent Luna-12E routed topology. This superseding workflow
dispatch does not authorize a bootstrap trainer, amend A14, or authorize any
later Luna. No bootstrap trainer is authorized by this ACP.

## Rollback plan

Restore the contract and workflow documentation to baseline revision
`396504dbf240509fb897a37965ec9fee123d17d3` if the owner rejects the governance
change. Existing implementation and artifacts remain valid as historical
software-reference work; do not delete experiment evidence. A later accepted
ACP may supersede this proposal after evidence review.
